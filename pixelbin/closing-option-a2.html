Endpoints

The user sees one prompt bar. Engineering builds nine variants of it. Each maps to a different API endpoint and model configuration across Image, Video, and Pixie modes. Video generation alone required three separate implementations — text-to-video, image-to-video, and motion control — each calling a different AI model. The Figma file was structured so any engineer could trace a variant back to its specific flow, state, and edge case without a walkthrough.

Constraints were documented as deliberately as features. The batch editing toolbar ships with 6 tools instead of 7 — prompt-based editing was excluded because it requires per-image intent and doesn't scale to batch operations. The AI Influencer's structured interview — 5 questions covering niche, demographic, purpose, aesthetic, and characteristics — was designed to map directly to API parameters, so engineering could build the persona endpoint from the design spec alone.

No intermediary between design and engineering. 170 frames organised by flow. Every frame annotated with its state, transitions, and edge cases. 57 components built for consistency across all 8 flows. The design stayed unified. The engineering became specific.

The core generation and editing flows are live and serving users. Image generation, video generation, upload-and-edit, and select-and-edit shipped in the first release.

Campaign planning, batch mode, and the AI influencer flow are shipping next. The design is complete and handed off — engineering is building against the same 170-frame prototype.

V1 explored 14 flows. V2 cut to 5. The dev handoff expanded to 8 — not because design added features, but because engineering needed video generation split into separate model endpoints. The design stayed unified. The engineering became specific.
